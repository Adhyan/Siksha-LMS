# Siksha

A local demonstration of a corporate learning and early-career opportunity platform. It includes a responsive Next.js sign-in and dashboard experience backed by a FastAPI API and a persistent SQLite development database.

## What works in this prototype

- Published internship opportunities with search and application submission.
- Candidate-owned application listing and organization-admin decisions, with backend role checks, immutable final decisions and exactly-one internship participation creation on acceptance.
- Course catalogue, enrolment and lesson completion records with progress derived from saved completions.
- Workshop catalogue and unique registrations.
- Notification listing and read state API.
- Public certificate status lookup endpoint (seedable record only; full issuance and PDF generation are not implemented).
- Separate candidate, mentor and organization-admin workspaces. Candidates track applications and internships; organization admins review applications and assign accepted interns to scoped mentors; mentors see only candidates assigned to their own account.
- Persistent light/dark theme toggle on the sign-in screen and in each workspace.
- Workshop navigation opens a registration pop-up; the notification bell opens the signed-in user’s notification panel with read-state updates.
- Password-verified local demonstration accounts with random revocable sessions, responsive navigation, meaningful empty and error states, and API health/readiness endpoints.

## Stack and scope adjustments

- Frontend: Next.js App Router, React, TypeScript, responsive CSS and Lucide icons.
- Backend: FastAPI, Pydantic, Python standard-library SQLite.
- Workspace inspection found no existing source, Git executable, Docker, PostgreSQL client, SQLAlchemy or Alembic. To keep the prototype runnable locally, this iteration uses SQLite. PostgreSQL, SQLAlchemy 2.x and Alembic remain required before production use.
- Development identity uses fixed demo bearer tokens, not real authentication. No managed identity provider, email, object storage, malware scanner, PDF generator or QR provider is configured.

## Prerequisites

- Node.js 20.9+ and npm.
- Python 3.10+.
- Network access for the first npm/pip dependency installation.

## Install and configure

Copy `.env.example` to `.env` if you want to adjust settings. Do not put real credentials into the local demo file. The frontend defaults to `http://localhost:8000/api/v1`; the backend stores its database at `backend/data/lms.db`.

```powershell
cd frontend
npm install
cd ..
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
```

## Run

Open two terminals at the repository root:

```powershell
python -m uvicorn backend.app.main:app --reload --port 8000
```

```powershell
cd frontend
npm run dev
```

Open `http://localhost:3000`. API docs are at `http://localhost:8000/docs`. The database and demonstration catalogue are initialized repeatably on API startup.

### Demo accounts

Sign in with one of these local-only accounts:

| Role | Email | Password |
|---|---|---|
| Candidate | `student@demo.local` | `StudentDemo!2026` |
| Organization admin | `admin@demo.local` | `AdminDemo!2026` |
| Mentor | `mentor@demo.local` | `MentorDemo!2026` |

The app issues random bearer tokens with an eight-hour expiry and stores only token hashes; sign out revokes the active session. These fixed demo passwords must never be used outside a local development database.

## Data and API

SQLite creates its schema through `backend/app/database.py`; this is not a migration system. Delete `backend/data/lms.db` only when you intentionally want a clean demo dataset. API routes are under `/api/v1`, with OpenAPI generated by FastAPI. Main endpoint groups currently cover identity, opportunities/applications, courses/progress, workshops/registrations, notifications and public certificate lookup.

## Architecture and security

The frontend contains the single page demonstration interface in `frontend/app/page.tsx`, global responsive tokens/styles in `frontend/app/globals.css`, and uses fetch to communicate with FastAPI. The backend keeps routes in `backend/app/main.py`, identity/role checks in `backend/app/auth.py`, and local persistence in `backend/app/database.py`.

Application ownership is enforced in SQL queries. Application decisions require an organization administrator and write an audit record. Course lesson completion requires enrolment. Workshop registration and applications have database uniqueness constraints. Public certificate lookup selects only its approved public fields. This is a foundation, not a complete authorization/security review.

Do not store sensitive profiles or files in this demo. Local password hashing and sessions are demonstration-only; there is no account registration, email verification, password reset, managed identity provider, MFA, CSRF defenses, rate limiting, tenant membership administration, secure object uploads, ZIP validation/scanning, email delivery, durable jobs, certificate issuance/revocation, or production audit retention. Privacy, retention and applicable Indian data-protection requirements require institutional/legal review; this software does not claim compliance.

Configure provider credentials only in a secret manager and deploy only after security review.
